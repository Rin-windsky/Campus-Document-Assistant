## 一、项目概述

### 1.1 项目背景

高校校园中存在大量分散的规章制度、办事流程和通知公告，师生在查询这些信息时往往需要在多个网站、部门之间反复跳转，效率低下。针对这一痛点，我们开发了 **「校问必答」校园智能文档助手**——一个集**统一检索、智能问答、办事导航**于一体的一站式校园服务平台。

### 1.2 核心理念

| 理念 | 释义 |
|------|------|
| **查得到** | 统一检索校内所有制度文件，打破部门信息壁垒 |
| **答得对** | 基于文档内容进行智能问答，每条回答均可追溯原文出处 |
| **给依据** | AI 回答附带引用来源，确保信息的权威性与可信度 |

### 1.3 适用范围

- **服务对象**：福州大学全体师生（本科生、研究生、教职工）
- **覆盖范围**：教务管理、奖助学金、学籍事务、宿舍管理、校园通知、学院信息等
- **文档库规模**：现有 20 份核心文档，支持动态导入扩展（PDF/DOCX/XLSX 格式）

## 二、技术架构

### 2.1 技术选型

| 技术领域 | 选型方案 | 版本 | 选型理由 |
|----------|----------|------|----------|
| **前端框架** | Vue 3（Composition API） | 3.5+ | 性能优异、生态成熟、响应式系统强大 |
| **构建工具** | Vite | 8.0+ | 极速冷启动、HMR 热更新、原生 ESM 支持 |
| **路由管理** | Vue Router | 5.0+ | 官方路由方案，支持路由守卫与懒加载 |
| **状态管理** | Pinia | 3.0+ | Vue 3 官方推荐的轻量级状态库 |
| **HTTP 客户端** | Axios | 1.16+ | 拦截器丰富、支持文件上传进度、取消重复请求 |
| **动画引擎** | GSAP + ScrollTrigger | 3.15+ | 专业级动画库，支持滚动驱动动画 |
| **Markdown 渲染** | marked | 18.0+ | 轻量快速，将 AI 回答渲染为富文本 |
| **PDF 解析** | pdfjs-dist | 5.7+ | 客户端 PDF 文本提取，用于关键词检索 |
| **DOCX 解析** | mammoth | 1.12+ | DOCX 转 HTML/纯文本转换，支持文档预览 |
| **XLSX 解析** | xlsx（SheetJS） | 0.18+ | Excel 文件解析与 HTML 表格预览 |
| **CSS 变量系统** | 原生 CSS Custom Properties | — | 统一的主题色、间距、阴影体系 |

### 2.2 核心技术栈总览

```
Vue 3 + Vite
├── 路由层：Vue Router 5（路由守卫、权限控制）
├── 状态层：Pinia（auth / todo / notification / counter）
├── 网络层：Axios（拦截器、Token管理、防重复提交、错误码映射）
├── 动画层：GSAP + ScrollTrigger（入场动画、滚动驱动动画）
├── 视图层：组件化单文件组件（SFC）
│   ├── 5 个页面视图（Home、Chat、Docs、Service、Login）
│   ├── 2 个通用组件（Navbar、UserProfileModal）
│   └── 2 个业务详情页（CardReplacement、ServiceDetail）
├── 样式层：CSS Custom Properties + Scoped Style
└── 构建层：Vite + ESLint + Prettier
```

## 四、功能模块详述

### 4.1 首页门户（Home.vue）

**功能定位**：用户登录后的默认着陆页，提供全局搜索入口和个性化信息仪表盘。

**核心功能**：

- **搜索入口**：居中搜索框，支持输入问题一键跳转 AI 问答；下方提供 4 个高频搜索标签（奖学金、转专业、宿舍报修、休学办理）
- **数据看板**：展示平台核心数据：规章制度 2860+、办事指南 1240+、通知公告 580+、覆盖部门 15 个（数字带 GSAP 滚动动画）
- **我的待办**：同步 Pinia todoStore 的待办事项列表，点击切换完成状态，支持紧急标记
- **快捷服务**：6 个常用校园服务卡片，支持编辑模式自定义显示/隐藏（localStorage 持久化）
- **热门问题**：5 个高频咨询问题，带分类标签和浏览量，点击直接跳转 AI 问答
- **最新通知**：同步 notification store 的最新通知列表，点击标记已读并跳转知识库

**动画设计**：
- Hero 插图 CSS 动画淡入 + 微放大
- 标题区 Badge → 标题 → 描述 → 搜索框 → 提示标签 → 数据指标依次弹入
- 数据指标使用 GSAP snap 功能实现数字滚动效果
- 待办列表、快捷服务、热门问题、最新通知、Footer 各区块使用 ScrollTrigger 触发入场

---

### 4.2 AI 智能问答（Chat.vue）

**功能定位**：基于校园文档库的智能问答系统，支持多轮对话和引用溯源。

**核心功能**：

- **多轮对话**：支持创建多个独立会话，会话历史保存到后端，切换会话可回顾历史消息
- **三层 AI 回答引擎**：
  - 第一层：调用后端 API（`/chat/ask`）进行 AI 语义问答
  - 第二层：后端不可用时自动降级为客户端文档关键词搜索（基于知识库本地解析 + localStorage 缓存）
  - 第三层：完全离线时使用预置高频问答兜底（奖学金、转专业、休学、宿舍 4 大主题）
- **引用溯源**：AI 回答附带引用来源，点击引用卡片在右侧面板显示文档详情与原文片段
- **三栏布局**：左侧会话历史 → 中间对话区 → 右侧引用详情/匹配文档
- **Markdown 渲染**：AI 回答支持 Markdown 格式（标题、列表、表格、代码块、引用块等）
- **消息操作**：复制回答、标记有用
- **欢迎引导**：首次进入显示欢迎界面和推荐问题快捷入口
- **URL 参数跳转**：支持通过 `?q=问题` 参数直接触发问答

---

### 4.3 知识库管理（Docs.vue）

**功能定位**：校园文档的统一管理平台，支持浏览、搜索、预览、导入。

**核心功能**：

- **分类筛选**：按 8 大分类（全部分类、教务管理、学生事务、宿舍管理、奖助学金、培养方案、校园通知、学院信息）筛选文档
- **部门筛选**：按发布单位（教务处、学生处、后勤管理处、各学院）筛选
- **全文搜索**：搜索文档标题、关键词、发布单位
- **双视图模式**：网格视图 / 列表视图切换
- **多格式文档预览**：选中文档后在右侧面板实时预览
  - PDF 预览：通过 iframe 直接渲染
  - DOCX 预览：使用 mammoth 将 Word 转为 HTML 预览
  - XLSX 预览：使用 SheetJS 将 Excel 转为 HTML 表格预览
  - 纯文本预览：对于无法在线预览的格式，提取纯文本显示
- **文档导入**（教师专属）：支持拖拽上传 PDF/DOCX/XLSX 文件，单个或批量，带进度提示。上传后自动刷新列表并发布通知
- **文档删除**：教师可删除已导入的文档
- **询问文档**：选中文档后可直接跳转 AI 问答，附带文档 ID
- **响应式设计**：大屏三栏（侧边栏 + 列表 + 预览），小屏折叠为单栏

### 4.5 登录注册（Login.vue）

**功能定位**：用户身份认证入口，支持登录和注册双模式。

**核心功能**：

- **登录/注册切换**：顶部标签式切换
- **表单验证**：
  - 学号/工号格式验证（6-12 位数字）
  - 密码最小长度验证（4 位）
  - 注册确认密码一致性验证
- **认证策略**：
  - 优先调用后端 API 进行身份验证（支持 JWT Token）
  - 后端不可用时自动降级为本地验证（保证离线可用性）
- **角色识别**：根据学号/工号自动判断学生/教师身份，加载不同的用户信息字段
- **登录态持久化**：Token 和用户信息存储在 sessionStorage，关闭浏览器后自动清除
- **路由守卫**：已登录用户访问 `/login` 自动跳转首页；未登录用户访问受保护页面自动跳转登录页
- **redirect 参数**：登录后自动跳回原始目标页面

**视觉设计**：
- 双面板设计：左侧品牌介绍区（渐变色背景 + 三大核心价值主张），右侧表单区
- 背景装饰：圆形光晕 + 网格纹理
- GSAP 入场动画：卡片淡入 + 品牌特性依次滑入

## 五、核心模块设计

### 5.1 统一请求模块（request.js）

**设计目标**：封装所有 HTTP 请求逻辑，提供统一的错误处理、Token 管理和请求优化。

**架构设计**：

```
Axios 实例
├── 基础配置
│   ├── baseURL: 从环境变量 VITE_API_BASE 读取
│   ├── timeout: 30 秒
│   └── Content-Type: application/json; charset=UTF-8
├── 请求拦截器
│   ├── 防重复提交：GET 之外的方法自动取消前一个相同请求
│   ├── Token 自动注入：白名单外所有请求自动带 Authorization: Bearer xxx
│   └── GET 防缓存：每个 GET 请求自动附加 _t 时间戳
├── 响应拦截器
│   ├── 统一响应格式处理：{ code, data, message }
│   ├── 业务错误码映射：0/200 为成功，其他按映射表解析
│   ├── 401 自动处理：清除登录态 + 跳转登录页
│   └── 网络异常兜底：超时、断网、服务端错误分级处理
├── 便捷方法
│   ├── get / post / put / del / patch          # 标准 CRUD
│   ├── uploadFile(url, file, onProgress)       # 文件上传（带进度回调）
│   ├── downloadFile(url, fileName)             # 文件下载（Blob 方式）
│   └── batchRequest(tasks, limit)              # 批量请求（控制并发数）
└── Token 辅助
    ├── getToken() / setToken() / removeToken()
    └── 存储介质：sessionStorage
```

**错误处理策略表**：

| 场景 | 错误码 | 处理方式 |
|------|--------|----------|
| 参数校验失败 | 400/422 | 展示后端返回的校验信息 |
| 未登录/Token过期 | 401 | 自动清除本地状态 → 跳转登录页 |
| 无权限访问 | 403 | 展示"无权限"提示 |
| 资源不存在 | 404 | 展示"资源不存在"提示 |
| 请求过频 | 429 | 展示限流提示 |
| 服务端错误 | 5xx | 展示"服务器异常" + 控制台日志 |
| 超时 | ECONNABORTED | 展示"请求超时"提示 |
| 网络断开 | Network Error | 展示"网络连接失败"提示 |

**自定义错误类**：`ApiError` 包含 code、status、message、data 四个字段，便于业务代码做精确的错误处理。

### 5.2 客户端知识库（knowledgeBase.js）

**设计目标**：在不依赖后端的情况下，实现文档文本的客户端解析、缓存和关键词检索。

**核心能力**：

- **多格式文档解析**：
  - PDF：使用 pdfjs-dist 提取文本（按页遍历 textContent）
  - DOCX：使用 mammoth 提取纯文本 / 转换 HTML
  - XLSX：使用 SheetJS 提取各 Sheet 为 CSV 格式
- **智能缓存**：解析结果缓存到 localStorage，避免重复解析
- **关键词搜索算法**：
  - 中文分词：按空格、标点切分关键词，自动过滤停用词和短词
  - 短语匹配：合并相邻关键词做短语连写匹配
  - 评分排序：基于匹配次数打分，返回 Top 5 结果
  - 上下文摘录：每个匹配结果附带前后 60 字符的上下文片段
- **批量预加载**：支持并发控制地预加载多个文档

**降级策略**：当后端 AI 问答不可用时，Chat.vue 自动切换到本地关键词搜索，确保基本问答能力不中断。

### 5.3 用户认证模块（auth.js Store）

**设计目标**：管理用户登录状态、身份信息和头像，支持后端/本地双模式认证。

**核心特性**：

- **双重认证策略**：优先后端 API → 失败自动降级本地验证 → 保证离线可用
- **角色识别**：学号以"1"开头为学生，以"2"或"3"开头为教师
- **字段规范化**：`normalizeUserInfo()` 函数将后端不同命名的字段统一映射到前端字段名
- **头像处理**：智能解析头像路径（data URL / 完整 HTTP URL / 相对路径自动拼接域名），支持更换头像并同步到后端
- **登录态管理**：sessionStorage 存储，关闭浏览器自动清除（安全考虑）
- **兼容性处理**：兼容后端返回的旧格式用户数据，缺失字段用 mock 数据补全

## 六、动画与交互设计

### 6.1 动画技术栈

本项目采用 **GSAP (GreenSock Animation Platform) + ScrollTrigger** 作为动画引擎：

- **GSAP**：业界顶级的 JavaScript 动画库，支持 Timeline 编排、Stagger 交错、弹性缓动等高级特性
- **ScrollTrigger**：GSAP 的滚动插件，实现滚动驱动的入场动画
- **IntersectionObserver**：部分场景使用原生 API 替代 ScrollTrigger

### 6.2 动画清单

| 页面 | 动画元素 | 实现方式 | 效果描述 |
|------|----------|----------|----------|
| **Home** | Hero 插图 | CSS Keyframes | 1.2s 淡入 + 微放大 |
| **Home** | Hero 标题区 | GSAP Timeline | Badge → 标题 → 描述 → 搜索框 → 提示标签 → 数据指标依次弹入 |
| **Home** | 数据数字 | GSAP snap | 数字滚动动画（0 → 目标值，1.5s） |
| **Home** | 待办/快捷/热门/通知 | ScrollTrigger | 各区块随滚动依次入场 |
| **Home** | Footer | ScrollTrigger | 品牌 → 链接栏 → 版权信息依次淡入 |
| **Login** | 登录卡片 | GSAP from | 整体淡入 + 微放大 |
| **Login** | 品牌特性 | GSAP stagger | 三条特性依次从左侧滑入 |
| **Chat** | 三栏布局 | GSAP stagger | 侧边栏/聊天区/引用栏依次滑入 |
| **Chat** | 新消息 | CSS animation | 用户消息和 AI 回答带 msgIn 弹入动画 |
| **Chat** | 思考中 | CSS animation | 三点弹跳动画（dotBounce） |
| **Docs** | 侧边栏 + 搜索栏 | GSAP from | 侧边栏从左侧滑入，搜索栏从上方滑入 |
| **Docs** | 文档卡片 | GSAP stagger | 文档加载完成后卡片依次从下方浮现 |
| **Service** | 办事卡片 | GSAP stagger | 6 张服务卡片依次弹入 |
| **Service** | 底部插图 | IntersectionObserver | 滚动到附近时淡入 |
| **ServiceDetail** | 整页元素 | GSAP Timeline | 返回按钮 → 图标 → 标题 → 时间线 → 联系方式依次入场 |
| **CardReplacement** | 整页元素 | GSAP Timeline | 同 ServiceDetail，额外包含表单区域 |
| **Navbar** | 导航栏 | GSAP from | 页面加载时导航栏从上方滑入 |
| **Navbar** | 下拉面板 | GSAP fromTo | 通知/用户下拉面板带缩放 + 位移动画 |
| **全局** | 加载/提示 | CSS animation | 错误提示抖动（shake）、加载旋转（spin） |

### 6.3 动画设计原则

1. **克制不干扰**：动画持续时间控制在 0.35-0.75 秒，缓动函数统一使用 `power2.out`/`power3.out`
2. **层次递进**：使用 Timeline 编排，按视觉层级依次播放
3. **交互反馈**：所有可点击元素均配置 hover/active 状态过渡动画
4. **性能优先**：使用 transform/opacity 等 GPU 加速属性，避免 layout thrashing
5. **自动清理**：所有组件在 `onUnmounted` 时调用 `ctx.revert()` 清理动画实例

## 九、性能与健壮性设计

### 9.1 性能优化策略

| 策略 | 实现方式 | 效果 |
|------|----------|------|
| **文档解析缓存** | localStorage 缓存文档文本 | 避免重复解析大文件 |
| **请求去重** | Axios 拦截器中维护 pendingRequests Map | 防止重复提交 |
| **并发控制** | batchRequest() 支持限制并发数 | 批量请求不压垮服务 |
| **CSS GPU 加速** | 动画统一使用 transform/opacity | 流畅 60fps |
| **防页面缓存** | GET 请求自动附加 `_t` 时间戳 | 避免浏览器缓存旧数据 |
| **资源懒加载** | 插图通过滚动触发加载 | 减少首屏请求数 |

### 9.2 健壮性设计

| 策略 | 说明 |
|------|------|
| **后端不可用降级** | 登录/问答/文档加载均支持本地兜底 |
| **LocalStorage 异常容错** | 所有 localStorage 读写包裹 try-catch |
| **网络超时处理** | 统一 30s 超时，文件上传单独 120s |
| **401 自动重新登录** | 响应拦截器自动清除 Token 并跳转登录 |
| **路由守卫** | 基于 sessionStorage 检查登录状态，比 Pinia 更早执行 |
| **错误边界** | 每个请求/操作独立 try-catch，失败不影响其他功能 |
| **通知容量控制** | 通知列表最多 50 条，防止无限膨胀 |
| **待办去重** | 同一服务事项防止重复加入 |

### 9.3 安全性设计

| 策略 | 说明 |
|------|------|
| **sessionStorage 存储** | Token 和用户信息使用 sessionStorage，关闭浏览器自动清除 |
| **密码不在 URL 中** | 所有认证请求使用 POST 方法 |
| **输入双重校验** | 前后端双重校验：学号格式 (6-12位数字)、密码长度 (≥4位) |
| **API Token 白名单** | 登录/注册接口不携带 Token（避免循环依赖） |
| **头像上传限制** | 文件大小限制 512KB |

## 十、用户体验设计亮点

### 10.1 渐进增强

- **网络分层策略**：每个功能模块都设计了"后端优先 → 本地降级"的容错机制
  - AI 问答：后端 API → 客户端关键词搜索 → 预置问答兜底（三层保障）
  - 用户认证：后端登录 → 本地验证（双重保障）

### 10.2 微交互细节

1. **搜索框聚焦态**：聚焦时边框变主色 + 外发光效果
2. **发送按钮状态**：输入框有内容时按钮变色激活
3. **消息入场动画**：每条消息都有弹入效果（msgIn）
4. **通知红点**：有未读通知时导航栏显示红色计数徽标
5. **卡片悬停效果**：所有可点击卡片悬停时有抬升效果（translateY -2px）
6. **密码可见切换**：登录/注册表单支持密码明文切换
7. **表单摇动反馈**：错误提示出现时带 shake 动画
8. **加载状态**：所有异步操作都有 loading 状态（按钮禁用 + spinner）

### 10.3 辅助功能

- 表单支持键盘操作（回车跳转下一个字段 / 回车提交）
- 自定义滚动条样式（窄条 + 圆角）
- 选中文字颜色为暖砂色
- 清晰的视觉层级（标题 → 副标题 → 正文 → 辅助信息）

### 10.4 角色差异化

- **学生端**：可浏览所有文档，使用 AI 问答，查看办事流程，加入待办
- **教师端**：拥有学生全部功能，额外拥有文档导入和删除权限
